Install

Pour it once. Drink for years.

DayMug runs on one Mac or Linux computer; every other device — yours, or the people you share it with — just opens it in a browser. You type a few commands in a terminal, then finish in the browser. About ten minutes, most of it signing in to your AI account.

The whole path

Terminal: 1 · Node.js and your AI's CLI → 2 · run the installer. Browser: 3 · open it, create the admin → 4 · connect an AI account → 5 · chat. Phones, other computers, a team and config.yaml come after that, when you need them.

Before you start

A computerA Mac with Apple Silicon, or Linux on x86_64 or ARM64. Your own laptop is fine to try it; pick a machine that stays on (home server, NAS, VPS) if you want it from your phone or for a team.
A normal user accountThe installer refuses to run as root. On a fresh server, create a user and log in as it first.
An AI planA Claude subscription, a ChatGPT plan with Codex, or an API key (Anthropic, OpenAI, or a compatible endpoint).
Not neededDocker, a database server, a cloud account, a domain name.

Where will DayMug run? It changes one thing, in Step 3:

DayMug runs on…You first open it…
the computer in front of youin that computer's browser.
a server you reach over SSH (VPS, home server, NAS)through an SSH tunnel from your own computer. Opening it to other devices comes afterwards.

Step 1 · Node.js and your AI's CLI terminal

Run these on the machine DayMug will live on. Agents run on Node.js 18 or later, and the installer can't install Node.js for you: 

node --version   # v18 or later? good. Otherwise: your distro's package, NodeSource or nvm
node --version   # v18 or later? good. Otherwise:
brew install node

Then install the command-line tool of the AI you'll use. DayMug drives it, and its Log in button runs it for you in Step 4:

You'll useInstall
Claude — subscription or API keynpm install -g @anthropic-ai/claude-code
ChatGPT / Codex, or an OpenAI-compatible API keynpm install -g @openai/codex

Do this before the installer: the service it registers remembers the PATH of the shell you install from, so tools added later in a new location (a new nvm version, say) stay invisible to DayMug until you re-run the installer.

Step 2 · Run the installer terminal

one line  — linux 
# as your normal user, not root
$ curl -fsSL https://github.com/DayMug/DayMug/releases/latest/download/install.sh | bash
one line  — macOS · apple silicon 
# in Terminal, as your normal user
$ curl -fsSL https://github.com/DayMug/DayMug/releases/latest/download/install.sh | bash

In about a minute it:

  1. Downloads the latest release for your machine and checks its checksum.
  2. Asks to install the Claude Agent SDK with npm if it's missing — answer Y (just Enter).
  3. Lays out ~/.daymug/: the binary, a default config.yaml, the database and logs.
  4. Registers a systemd user service and starts it. Registers a LaunchAgent (it starts on login) and starts it.

It ends with a summary like this:

==> DayMug v0.0.20 installed: /home/you/.daymug/daymug
    Service:  started
    Open:     http://127.0.0.1:8090 and create the first admin account
    Next:     add an AI provider under Settings → Administration → Providers & models
    Deps:     installed @anthropic-ai/claude-agent-sdk
    Trouble:  ~/.daymug/daymug doctor
    Log:      ~/.daymug/logs/daymug.log
    Public access (reverse proxy / LAN): https://github.com/…

Check the Service and Deps lines:

If it saysDo this
Service: started, and every Deps line is installed … or Codex (optional)Nothing — go on.
Deps: Node.js 18+ not found or … is too oldInstall Node.js (Step 1), then run the installer again.
Deps: Claude needs: npm install … or … install failedRun the npm command it prints, then the installer again.
Deps: Codex (optional)Ignore it unless you'll use Codex — then see Step 1.
Service: installed, not started or not registeredRun the command printed after the dash.
On a server: keep it running after you log out

By default systemd stops a user's services when their last session ends — closing SSH would stop DayMug, and it wouldn't come back after a reboot. The installer warns ! Linger is off when that applies. Turn lingering on once: 

sudo loginctl enable-linger "$USER"

Re-running the installer is always safe: it replaces the binary and keeps your config.yaml and data. Flags (a specific version, no prompts, no service) are under Installer options.

Step 3 · Open it and create the admin browser

DayMug listens on 127.0.0.1:8090, so at first only the machine itself can reach it. That's on purpose: whoever opens an empty instance first becomes its admin.

  • On the computer in front of you: open http://127.0.0.1:8090.
  • On a server: on your own computer, open a tunnel and leave it running, then open http://127.0.0.1:8090 in your own browser. 
    ssh -N -L 8090:127.0.0.1:8090 you@your-server

The page says Create the admin. The username must be the part of the email before the @, and the password needs at least 8 characters. That's your login from now on, and DayMug also creates your first agent, named after you.

Step 4 · Connect an AI account browser

Open the account menu → Admin settings → Providers & models (on a phone: Settings → Administration → Admin Panel → Providers & models) and click Add account.

  1. Pick how it connects The agent framework (Claude Code or Codex), the access (Official account login for a subscription, or API key), and the vendor. A Codex account also needs its own credential directory, e.g. ~/.daymug/accounts/codex. Save it.
  2. Sign in With an account login, click Log in. A terminal opens in the browser. Claude prints a URL: open it, approve, and paste the code back. Codex shows a link and a one-time code. This works even when the server is somewhere else. With an API key there's nothing to sign in to.
  3. Add models Type at least one model id (e.g. claude-sonnet-5) and set the summary model, a small cheap one such as claude-haiku-5, which writes conversation titles. DayMug ships no built-in list, so an account without models offers nothing to pick.
  4. Check account It sends one real test message and tells you what's wrong if it fails.

Every field, and compatible endpoints: Providers & models.

Step 5 · Chat browser

Open the agent named after you in the sidebar and ask it something. If it answers, you're set up. More agents, each with its own purpose and folder: Settings → Agents → New Agent. Next: Chat.

Reach it from other devices

Create the admin first (Step 3). Then pick the simplest option that fits:

Option A · Your home or office network, or a private VPN

Quickest: no certificates, no proxy. In ~/.daymug/config.yaml, change server.addr from 127.0.0.1:8090 to 0.0.0.0:8090, then restart: 

systemctl --user restart daymug.service
launchctl kickstart -k "gui/$(id -u)/com.daymug.daymug"

Other devices open http://<this machine's IP>:8090. With a private VPN such as Tailscale or WireGuard on both devices, the VPN address works from anywhere.

Plain HTTP

This sends passwords unencrypted, so use it only on a network you trust. On a VPS with a public IP, 0.0.0.0 opens the port to the whole internet. Bind to the VPN address instead (e.g. 100.64.0.5:8090), or take Option B.

Option B · A domain with HTTPS

For a server on the internet, or a team. Keep server.addr on 127.0.0.1 and put a reverse proxy that terminates TLS in front of it.

  1. Point DNS Point an A / AAAA record at this machine.
  2. Issue a cert with Let's Encrypt 
    sudo apt install -y nginx certbot python3-certbot-nginx
sudo certbot --nginx -d chat.example.com
    Certbot installs a renewal timer automatically.
  3. Add an nginx server block In /etc/nginx/conf.d/daymug.conf. WebSockets need the Upgrade headers and a long proxy_read_timeout, and raise client_max_body_size, because nginx's default of 1 MB rejects most file uploads with 413 Request Entity Too Large: 
    server {
  listen 443 ssl http2;
  server_name chat.example.com;
  ssl_certificate     /etc/letsencrypt/live/…/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/…/privkey.pem;
  # nginx defaults to 1m; DayMug takes 25 MB per chat
  # attachment and 200 MB per file-browser upload
  client_max_body_size 200m;
  location / {
    proxy_pass http://127.0.0.1:8090;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header Upgrade           $http_upgrade;
    proxy_set_header Connection        "upgrade";
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 3600s;
  }
}
  4. Reload sudo nginx -t && sudo systemctl reload nginx
  5. Tell DayMug its address Set server.public_url: https://chat.example.com in config.yaml and restart, so links in notifications open the right page.
  1. Use the proxy or tunnel you already run Point it at 127.0.0.1:8090. The Linux tab shows a complete nginx example.
  2. Tell DayMug its address Set server.public_url in config.yaml to the HTTPS address and restart.

Caddy, Traefik, or a tunnel you run yourself (cloudflared, frp) work too, with the same rules. Keep WebSocket upgrades and a read timeout of at least 3600 s, forward Host and X-Forwarded-Proto, and allow request bodies of at least 200 MB.

Share it with a team

  • Add people under Admin settings → Users, or let them sign in with your SSO. See Users & SSO.
  • Agents of non-admin users can be jailed with bubblewrap, but the sandbox is off until you turn it on. Do that before handing out accounts. See Sandbox.
  • Use Option B, so passwords never cross the network in plain text.

config.yaml

~/.daymug/config.yaml works as installed. Restart the service after editing it. The keys people change first:

server.addrWhere it listens. Default 127.0.0.1:8090; see other devices.
server.public_urlThe address people open it at, used for links in notifications.
admin.bootstrap_usernamesUsernames made admin again on every start, so you can't lock yourself out. The default lists admin; put your own username there.

Every field: config.yaml.

If something's wrong

Run ~/.daymug/daymug doctor. It checks the agent runtime, the config, the service and whether the server answers, and prints the fix for each failure. Then look at the log: 

journalctl --user -u daymug.service -n 50
tail -n 50 ~/.daymug/logs/daymug.log

Common errors and their fixes: Troubleshooting.

Other ways to install

Docker

The repository has a Dockerfile and a compose file. The image bundles Node.js, the Claude CLI and Codex, so you can skip Step 1. You build it yourself: 

git clone https://github.com/DayMug/DayMug.git && cd DayMug
docker compose up -d --build   # then continue at Step 3: http://127.0.0.1:8090

The trade-offs: there is no bubblewrap sandbox, and no in-app upgrade, so you upgrade with git pull && docker compose up -d --build. Details are in docs/guides/docker.md.

Build from source

For an Intel Mac, another platform, or hacking on DayMug. You need Go 1.25+, Node.js 20+ and pnpm 10+.

build a single binary
git clone https://github.com/DayMug/DayMug.git && cd DayMug
make build                       # frontend + embedded binary → backend/bin/daymug
./backend/bin/daymug bootstrap   # lay out ~/.daymug/ and start the service

Then continue at Step 3. For hot-reload development, see CONTRIBUTING.md in the repository.
